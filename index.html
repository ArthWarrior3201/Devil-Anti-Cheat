What it is

An anti-cheat that doesn't trust the client

Most cheats work by lying to the server — "I'm here," "I hit them," "I can see everyone." Devil flips the model: the server simulates movement, hits and visibility, and the client only ever sends what it wants to do. A client can't cheat about a result it was never allowed to assert.

Features

What's in the box

🛡️

Server authority

Movement, aim, hit detection and visibility are resolved on your server. Aimbot, wallhack and speedhack lose their footing.

🧬

Hardware-hash bans

Flag a machine by an opaque hardware hash — never raw IDs, never the OS key. The ban lives on your server, so it's reversible.

✍️

Signed integrity

Verify the game's own files against an Ed25519-signed manifest. Patched binaries are caught; forged manifests are rejected.

🖥️

VM signal

Detects virtual machines as a scored signal your backend can weigh — configurable, because it's one input among many.

♻️

Reversible enforcement

Every ban carries evidence and a rule version. Appeals lift a ban with one server write. No permanent damage, ever.

🔌

Drop-in SDK

One DevilClient call at launch. Point it at your server with a protocol file and you're wired in.

Architecture

Public SDK, private core

The client code is open because hiding it buys nothing — it already runs on the player's PC. The parts worth protecting stay private by living on your server, not behind obfuscation.

Integration

Wire it into your game

Add the SDK

Drop the client_sdk package into your game client.

Generate your signing keys

Create an Ed25519 keypair. Keep the private key on your build server; embed the public key in your game.

# one time, on your build machine
from client_sdk import integrity
priv, pub = integrity.generate_keypair()  # store priv secretly

Sign a manifest at release

Hash your shipped files and sign the manifest. Ship the signed manifest with the build.

man = integrity.build_manifest(root, files, version="1.0.0")
signed = integrity.sign_manifest(man, priv)

Point the SDK at your server

Drop a devil_protocol.json next to your client (endpoint, auth, field names, fail-mode). See the sample in the repo.

Check at launch

One call gates the launch: integrity → VM policy → hardware blacklist.

from client_sdk import DevilClient, LaunchPolicy

client = DevilClient(public_key_hex=PUB, protocol_config_path="devil_protocol.json")
d = client.verify_launch(game_root=".", signed_manifest=signed, policy=LaunchPolicy())
if not d["allow"]:
    show(d["message"]); exit(1)   # e.g. "SORRY, YOU ARE BANNED"

Run the authoritative core on your server

Implement the server_core_interface contracts so movement, hits and visibility are resolved server-side. This is where real anti-cheat strength lives.
